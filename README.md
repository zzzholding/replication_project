# Replication Project

Простая модель репликации данных в распределённой системе, реализованная на Python.

Проект демонстрирует, как данные могут храниться на нескольких узлах, синхронизироваться между серверами и как могут возникать конфликты консистентности.

## Возможности проекта

- **Три узла (Nodes):** Созданы три независимых узла — Node 1, Node 2 и Node 3.
- **Хранение данных:** Каждый узел хранит информацию о студенте (имя и возраст).
- **Синхронизация данных:** Изменения на одном узле могут передаваться другим узлам.
- **Master–Slave:** Один главный узел передаёт обновления двум подчинённым узлам.
- **Multi-Master:** Несколько узлов могут самостоятельно изменять данные и передавать обновления остальным.
- **Нарушение консистентности:** Смоделирована ситуация, когда на разных узлах хранятся разные значения.
- **Разрешение конфликтов:** Выполняется повторная синхронизация узлов с использованием выбранного источника данных.

## Как работает проект

### 1. Создание узлов

Создаются три узла с одинаковыми начальными данными:

```python
node1 = Node("Node 1")
node2 = Node("Node 2")
node3 = Node("Node 3")
```

Каждый узел хранит имя студента и его возраст.

### 2. Репликация Master–Slave

Node 1 выступает в роли главного сервера (Master).

При изменении данных на Node 1 обновлённая информация копируется на Node 2 и Node 3.

### 3. Репликация Multi-Master

Несколько узлов могут изменять собственные данные и передавать обновления другим узлам.

В проекте сначала Node 1 изменяет данные, а затем Node 2 самостоятельно выполняет новое обновление.

### 4. Консистентность и разрешение конфликтов

Моделируется ситуация, когда на разных узлах хранятся разные значения одного и того же параметра.

Для восстановления консистентности выбирается один узел в качестве источника достоверных данных. После этого его данные копируются на остальные узлы.
